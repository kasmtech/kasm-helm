# Changelog

All notable changes to the kasm-agent-crds chart are documented here.

## [Unreleased]

### Fixed

- `Chart.yaml`'s description listed three of the five CRDs; it names the `pools.kasm.ai` pair too.

### Changed
- CRDs synced from the operator (workspace run modes): `Agent.spec.workspaceSecurity` (`rootMode` `userns`/`host`/`forbid`, `userNamespaces` `rootOnly`/`always`, `rootFeatures` `promote`/`downgrade`/`reject`, `profile` `baseline`/`restricted`, `sudo`, `supplementalGroups`, `fsGroupChangePolicy`) is how session containers run: uid 1000 by default, and uid 0 in a pod user namespace for an image that needs root. Two CEL rules reject `profile: restricted` with `rootMode: host` and `sudo` with `profile: restricted`. `KasmWorkspace.spec.hostUsers` (`false` puts the pod in its own user namespace). Schema only.
- CRDs synced from the operator (image puller: per-node DaemonSets with a storage budget): `KasmImagePuller` is reworked around a per-node holder pod plus one pull pod at a time within a disk budget. New `spec.storage` (`ImagePullerStorage`: `reservedBytes`/`reservedPercent`, `evictionPercent`, `unpackFactor`, `maxConcurrentPulls`), `PulledImage.priority` (pull order), and a much richer `status` (`holders`, per-node `nodes[]` with budget/staged/pulling/skipped, `pullFailures[]`, `summary.imagesSkipped` replacing `imagesPending`, `status.daemonSet` gone). `Agent.spec.imagePuller` gains the same `storage`, and `Agent.status` a new `ExtraImagesStaged` condition. Schema only.
- CRDs synced from the operator: `Agent.spec.sessionProxy` gains `internalService` (a second Service in front of the same proxy pods — e.g. an internal `LoadBalancer` on a private subnet so a control plane on a peered network reaches this agent without a public path; same shape as `service`, pair it with split-horizon DNS) and `resolver` (the DNS server nginx uses to resolve a downstream agent's hostname for the `/desktop` relay, whose upstream is an nginx variable; unset uses the pod's cluster DNS). Schema only.
- CRDs synced from the operator (a ServiceAccount of the sessions' own): `KasmWorkspace.spec.serviceAccountName` names the ServiceAccount the workspace pod runs under; the operator creates `<agent>-workspace` per Agent (no RBAC, token automount off) and the agent sets it on every session, so cluster policy such as an OpenShift SecurityContextConstraint can be granted to sessions without widening the namespace's `default` account. Empty keeps the namespace default. Schema only.
- CRDs synced from the operator (warm-pool controllers moved off the main line): the `pools.kasm.ai` pair — `warmpools` and `warmpoolinstances` — is removed. The operator no longer owns them, so this chart no longer ships them; it now carries three CRDs, `agents`, `kasmworkspaces` and `kasmimagepullers` in `agent.kasm.com`. A WarmPool CRD already on a cluster is left in place — this chart's `helm.sh/resource-policy: keep` never deletes a CRD — so remove `warmpools.pools.kasm.ai`/`warmpoolinstances.pools.kasm.ai` by hand if nothing else uses them.
- CRDs synced from the operator: `KasmWorkspace`'s `healthCheck` (`WorkspaceHealthCheck`) description now spells out the default readiness — a bash exec that polls the workspace port every 50 ms, so a pod goes Ready the moment VNC listens rather than on the next whole-second probe tick; an image without bash must set `readinessProbe` (e.g. a plain TCP probe). Description only.
- CRDs synced from the operator (bound where the session proxy connects): `Agent.spec.sessionProxy` gains `networkPolicy` (`enabled`, `extraEgress`) — an opt-in egress NetworkPolicy the operator creates for the proxy pods. A session's route carries the user's authenticated request to whatever address it names, so the policy limits the proxy's egress to where it has business (its own and the control plane's namespaces, DNS, the API server) plus `extraEgress` (rules in NetworkPolicy's own terms, e.g. an `ipBlock` for a control plane outside the cluster); ingress stays open. Schema only.
- CRDs synced from the operator (a session proxy that scales and stays put): `Agent.spec.sessionProxy` can now be sized to load and placed deliberately, and its routing default flips. `routing` defaults to `dynamic` (nginx resolves each session per request from a table the sidecar keeps current, with no reload) instead of `static`; the default `kasmweb/nginx` image carries the njs module it needs. New sizing and placement fields: `resources` and `sidecarResources` (set proxy requests so a node autoscaler counts the pod instead of packing it onto a node it then removes), `nodeSelector`, `tolerations`, `affinity`, `topologySpreadConstraints`, `podDisruptionBudget` (exactly one of `minAvailable`/`maxUnavailable`), `drainTimeoutSeconds` (default 300 — how long a stopping pod keeps serving the streams it already holds), and `nginx` (`workerProcesses`, `workerConnections`) for one pod's connection capacity. Two mutually exclusive ways to size the Deployment by live session count: `autoscaling` (`sessionsPerReplica`, `minReplicas`, `maxReplicas`, `scaleDownStabilizationSeconds`), which the operator drives, or `externallyScaled`, which leaves the replica count to a KEDA `ScaledObject` or HPA. `Agent.status` gains `sessionProxy` (`replicas`, `desiredReplicas`, `scaleDownSince`). Schema only.
- CRDs synced from the operator (stop the image puller's disk-pressure eviction loop): `KasmImagePuller.status.nodeBackoffs[]` gains `diskEvictions`, `imageSetHash`, `recoveredAt` and `suspended` — the operator now stages images one at a time, holds a node's back-off through the DaemonSet, and suspends a node after three disk-pressure evictions for the same image set. Status only.
- CRDs synced from the operator: `Agent` gains `spec.sessionProxy.routing` (`static` or `dynamic`, default `static`) — `dynamic` has nginx resolve each session's workspace per request with no reload (needs a session-proxy image with the njs module). Schema only.
- CRDs synced from the operator (capacity that can grow): the `Agent` gains an opt-in `spec.workspacesAutoscaling` block with two independent halves. `enabled` (with `maxNodes` and `schedulingTimeoutSeconds`, paired with a new agent-set `KasmWorkspace.spec.schedulingTimeoutSeconds`) lets a session wait for a node autoscaler to add a node instead of failing when the pool is full. Nested `spec.workspacesAutoscaling.standby` (`enabled`, `replicas`, `externallyScaled`, `image`, required `priorityClassName`, `resources`) is a Deployment of low-priority placeholder pods that reserve room ahead of demand. Each works on its own — standby covers normal load, waiting covers the bursts — so `enabled` is optional and standby can run without it. `Agent.status.workspaces` gains `largestRequest` and `launchable`. Both default off; schema only.
- CRDs synced from the operator: `kubectl get agent` now answers whether the agent is working. `Agent.status` gains a `workspaces` object (`sessions`, `nodes`, `cores` — what the last heartbeat told the manager, `cores` being the reported capacity in image cores) and a `Registered` condition for whether the manager is accepting the agent's heartbeats. The default columns become `PHASE REGISTERED SESSIONS CORES WITHHELD MANAGER`, and `-o wide` adds `NODES`, `CPU%`, the `DEGRADED` reason, `ZONE` and the workspaces node selector. Status and columns only. A follow-up corrects the `serverID` field descriptions: when the spec pins no id the agent (not the operator) generates it, persists it in the `kasm-agent-state` ConfigMap and reports it in `status.serverID`.
- CRDs synced from the operator: `Agent` gains `spec.workspaceCPURequestPercent` (1-100, default 100) — the share of a workspace image's `cores` a session reserves as its Kubernetes CPU request, so lowering it bin-packs more sessions per node without touching any CPU limit. `Agent.status` also documents the new `ImagesWithheld` condition the agent writes on its own `Agent` when it withholds an image from the manager because no node has room for it.
- CRDs synced from the operator (2026-09-15, image-puller rollout gating): `KasmImagePuller.status.summary` gains `imagesPending`, and the spec descriptions state the operator's new rollout rule. A change to the image set is a new DaemonSet pod template, and the kubelet finishes a replaced puller pod's remaining pulls before it honours the deletion, so every rollout that landed mid-pull stacked another pod per node pulling the same images. The operator now applies a template change only once no puller pod is still pulling; images added or removed in the meantime accumulate and go out together, the CR reports `Progressing=True` with reason `RolloutDeferred` while it waits, and a pull that has given up (`ImagePullBackOff`) does not hold it. The image list is staged sorted, so a reordered catalog is not a rollout, and the DaemonSet's `maxSurge` is `100%` so nodes roll in parallel instead of one at a time. The chart carries only the schema.
- CRDs synced from the operator (2026-09-15, image-puller back-off bookkeeping): `KasmImagePuller.status.nodeBackoffs[]` gains `lastEvictedPodUID`, and the descriptions no longer promise that the puller's back-off excludes nodes through its DaemonSet pod template. That exclusion is gone: every change to the back-off list rolled the DaemonSet and aborted the pulls in flight on all nodes. The kubelet's own admission and the DaemonSet controller's back-off cover a node under pressure; `status.nodeBackoffs` stays as bookkeeping.
- CRDs synced from the operator (2026-09-15, server labels and workspace tolerations): `Agent` gains `spec.labels` (server labels advertised in every heartbeat) and `spec.workspacesTolerations` (tolerations for every workspace pod, also scoping the agent's puller and capacity report); `KasmWorkspace.status` and `KasmImagePuller.status.nodeBackoffs[]` gain `lastOOMKilledAt`, the termination time of the last OOM kill already counted, so a container that restarts before the next reconcile is still counted once.
- CRDs updated from the operator (2026-09-04): `Agent` gains `spec.sessionProxy.otel.endpoint` (session-proxy sidecar OTLP endpoint override; empty disables the exporter), and `KasmWorkspace.spec.fileMappings[]` gains `binaryData` (binary file content, mirrors a ConfigMap's `binaryData`) and `writable` (copy-on-start so the session user can edit the file).
- README lists all five CRDs, adding `warmpools` and `warmpoolinstances` in `pools.kasm.ai`; the regeneration hint says `make readme-all`; the first section links the docs index.

### Added

- Rancher catalog packaging: `catalog.cattle.io/*` annotations in `Chart.yaml` (hidden from the catalog, installed on the umbrella charts' behalf through their `auto-install` annotation, the CRD group it provides, version gates), a top-level `kubeVersion` and `app-readme.md`. No form: the chart has no values.
- Initial release: ships the same CustomResourceDefinitions as `charts/kasm-agent-operator/crds/` (agents, kasmworkspaces, and kasmimagepullers in the `agent.kasm.com` group) as ordinary Helm templates, so a release of this chart owns their lifecycle and `helm upgrade` applies schema changes — a hybrid alternative to the operator chart's bundled `crds/` install-time copy.
