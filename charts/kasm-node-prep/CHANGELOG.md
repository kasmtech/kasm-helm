# Changelog

All notable changes to the kasm-node-prep chart are documented here.

## [Unreleased]

### Changed

- `make kmm-install` now pins KMM's five images to the dated release tag (`v20260812-v2.7.0`) the staging registry actually publishes, instead of leaving the overlay's rolling `:latest` in place; `kmm-install-mirrored` pins the same tag (its former `:v2.7.0` did not exist upstream). Both targets and the README now say cert-manager is a prerequisite, which the overlay's webhook `Issuer`/`Certificate` require.
- `modules.v4l2loopback.sourceRef` default bumped from `v0.13.2` to `v0.15.4`. RHEL 9.8's 5.14.0-687 kernel dropped the `from_timer` helper that v0.13's timer-API probe relies on, so v0.13.2 fails there with `implicit declaration of function 'setup_timer'`; v0.15.4 compiles against every kernel tested (Ubuntu 22.04 5.15 GA and 6.8 HWE, RHEL 9.8 5.14, Amazon Linux 2023 6.12, openSUSE Leap 15.6 6.4, Azure Linux 3 6.6).
- `tuning.sysctls` writes each value to the node's `/proc/sys` directly instead of calling `sysctl -w`, so the builder image no longer needs a `sysctl` binary (procps).
- `tuning.swap` installs `util-linux` through the detected package manager only when `swapon`/`mkswap` are missing from the builder image (they are on `amazonlinux:2023` and the Azure Linux base images; `ubuntu` has them, so the default does no package operation).
- The missing-V4L2-core diagnosis names the package for the builder image's family: `linux-modules-extra-$(uname -r)` on Ubuntu (the `-generic`, `-aws`, `-gke` and `-azure` flavors all have one), `kernel-modules` on RHEL 8/9, Rocky and Alma, `kernel-modules-extra` on Amazon Linux 2023, `kernel-uek-modules` (UEK R7) or `kernel-uek-modules-desktop` (UEK R8) on Oracle Linux. Ubuntu's `-kvm` flavor still can never work.
- The Secure Boot `sign-file` helper is looked up under the kernel build tree on every family: Debian's `/usr/src/linux-headers-*` location is tried first, then `<build tree>/scripts/sign-file`.
- README trimmed to reference: the KMM Mode A/B runbook, the Secure Boot walkthrough, the swap kubelet prose and the builder-image Dockerfile now link their how-to pages, while the decision table, the registry rule, the safety check, sizing/force/zram, sysctls and the `sourcePath` semantics stay. `helm template` runs against the local chart, since this chart is not published; the KMM version is whatever `KMM_VERSION` pins in the Makefile. The HTML values-table template moved to the shared `_templates.gotmpl`.

### Fixed

- The KMM `Module` was named `<release>-kasm-node-prep-v4l2loopback`, which KMM v2.7.0's admission webhook refuses for every realistic umbrella install: it caps the name plus the namespace at 41 characters (`kasm-agent-kasm-node-prep-v4l2loopback` in `kasm-agent` is 48). Even `<release>-v4l2loopback` breaks it for ordinary pairs such as `kasm-agent-prod` in `kasm-agent-prod` (43), so the `Module` and its Dockerfile ConfigMap are now `<release>-v4l2[-dockerfile]` (`fullnameOverride` still replaces the release name), and the render fails with the same 41-character rule so the limit surfaces from Helm. Found on a Rocky Linux 9 k3s node with KMM v2.7.0.
- `tuning.swap` mis-detected its own active swapfile after a pod restart. The kernel renders each `/proc/swaps` path relative to the mount the file was activated through, so a replacement pod (an upgrade, a crash, a new builder image) saw a bare `/kasm.swap` instead of the full path, took the swap for missing, and failed `mkswap` on the in-use file every pass. Detection now reads `/proc/swaps` directly and accepts the chart-owned file name as well as the full path. Found on a Rocky Linux 9 node when the builder image was switched under an active swapfile.
- Ubuntu HWE kernels are built with a newer gcc than the release's `build-essential` provides, and their headers pin it (`CC = gcc-12` in the 6.8 HWE Makefile on 22.04) without depending on it, so the module compile failed on a 22.04 node running the HWE kernel. The reconcile script and the KMM Dockerfile now install the compiler named by the kernel's `CONFIG_CC_VERSION_TEXT` when it is missing: `gcc-<N>` on apt, and on the RPM families `gcc-toolset-<N>` put first on PATH, which is what Oracle's UEK R8 (a 6.12 kernel built with gcc 14 on the el9 userland, whose Makefile passes `-fmin-function-alignment=8`) needs.
- `tuning.sysctls` and `tuning.swap` were silently broken on any builder image without procps or util-linux (`rockylinux`, `almalinux`, `amazonlinux`, `azurelinux`, even `debian:12`): `sysctl -w` was not found, and neither were `swapon`/`mkswap`. Sysctls now need no binary at all and swap installs `util-linux` when it is missing (see Changed).
- **Security:** chart values were interpolated into the reconcile script (a root shell in a privileged DaemonSet on every node) and into the KMM build Dockerfile without shell quoting, so a crafted `modules.*.sourceRepo`, `sourceRef`, `sourcePath`, `tuning.swap.hostPath` or `tuning.sysctls.values` entry was executed as code. Every such value is now single-quoted with embedded quotes escaped, and sysctl keys and values are validated at render time.
- **Security:** a `modules.*.sourceRepo` URL carrying `user:password@` was stored verbatim in the script ConfigMap and printed by the clone log line on every reconcile pass. Such URLs are now rejected at render time; the clone log and error lines strip any userinfo regardless.

### Added

- Multi-family builder images for `method: build`. The reconcile script detects the package manager the builder image carries and installs the toolchain and the node kernel's headers through it: `apt-get` (Debian, Ubuntu) as before, and now `dnf`/`yum`/`microdnf` (RHEL 8/9, Rocky, Alma, Oracle, CentOS Stream, Fedora, Amazon Linux 2023 — the headers are installed by path, `/usr/src/kernels/$(uname -r)`, so `kernel-devel`, `kernel6.12-devel` and `kernel-uek-devel` all resolve), `tdnf` (Azure Linux 3) and `zypper` (openSUSE Leap, SLES). The rule this makes explicit: `image.*` must be the node's own distribution family **and** release, because the headers come from the builder image's repositories, never the node's; the default stays `ubuntu:22.04`, and a GKE Ubuntu 24.04 node needs `ubuntu:24.04`. An image with none of the six package managers logs an error naming all six; a pre-baked image still skips package installation on any family. The README carries the per-family package table and a builder-image-per-node-image table.
- The KMM in-cluster build Dockerfile does the same package-manager detection, so `method: kmm` with `kmm.build.enabled` works with an RPM-family builder image too. On RPM it passes `KERNEL_DIR=/usr/src/kernels/<kernel>` to the module's `make`, because a build container with only the headers package has no `/lib/modules/<kernel>/build` symlink.
- `modules.v4l2loopback.sourceRepoSecret` / `modules.wireguard.sourceRepoSecret`: an existing Secret (keys `username`, `password`) whose login the script hands to git through a credential helper, never through the URL (`method: build` only).
- `imagePullSecrets` for the DaemonSet, so the builder image can come from a private registry — the air-gapped path the `image.*` comments describe.

- Initial release: privileged DaemonSet that builds and loads the kernel modules Kasm Workspaces sessions depend on (v4l2loopback for webcam passthrough, WireGuard for older kernels), either compiling in-cluster (`method: build`, with airgapped/offline source support) or delegating the lifecycle to the Kernel Module Management operator (`method: kmm`).
- Adds node tuning: disabling swap and applying custom sysctls on matching nodes.
