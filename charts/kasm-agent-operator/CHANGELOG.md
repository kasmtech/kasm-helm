# Changelog

All notable changes to the kasm-agent-operator chart are documented here.

## [Unreleased]

### Changed
- CRDs synced from the operator: `Agent.spec.workspaceSecurity.driResource` names the extended resource a DRI device plugin advertises GPU render nodes as; when set, an image's `/dev/dri` devices request one of it instead of a hostPath mount.
- CRDs synced from the operator: `Agent.spec.workspaceSecurity.deviceAllowlist` lists which host devices an image's run config `devices` may pass through to its session pod (default: the DRI card and render nodes; `["none"]` passes none).
- CRDs synced from the operator (image pulls don't fail a workspace): `KasmWorkspace.status.imagesPulledTime` records when a pod's images reached its node; the operator's 70s readiness deadline counts from then instead of from creation, and a pull in progress (Ready reason `PullingImage`) is bounded by 15 minutes instead. Status only.
- CRDs and RBAC synced from the operator (sessions as pods): the operator runs each `KasmWorkspace` as a Pod it creates and deletes itself - no Deployment, ReplicaSet or per-session Service. `KasmWorkspace.spec.stopped` (stop and pause set it; resume clears it) replaces scaling a Deployment, and `spec.service` keeps only `ports`. `manager-role` grants `pods` create/delete/get/list/watch in a rule of its own (no longer update/patch); the `kasm-agent` ClusterRole drops `apps/deployments`.
- `kasm-nginx-sidecar` ClusterRole reads `pods` (`get`/`list`/`watch`) instead of `services`, synced from the operator: the sidecar now routes each session straight to its Ready workspace pod's IP rather than through a per-session Service, in both dynamic and static routing. Reads only.
- CRDs synced from the operator (image puller churn): `KasmImagePuller.spec.images[].priority` (and the `Agent`'s image-puller copy of it) is documented as a rank - the agent now writes each image's place in the order of how many sessions use it, not the count itself, so launches no longer rewrite the puller's spec - and `status.lastReconcileTime` as when a reconcile last changed the status. Descriptions only.
- CRDs synced from the operator (proxy scale-down one replica at a time): `Agent.status.sessionProxy` gains `lastScaleDownTime`, when the operator's session-proxy autoscaler last removed a replica. The next removal now waits a minute after it however often the `Agent` is reconciled; before, once `scaleDownStabilizationSeconds` had passed, the agent's frequent status writes let the autoscaler drop straight to its target, cutting the streams on every replica it removed. Status only.
- `resources` defaults: requests `100m` / `128Mi`, limits `1` / `512Mi` (were `100m` / `256Mi` for both). The requests stay small so the operator fits a small cluster; the limits leave room for about 1,000 concurrent sessions - the operator's informer caches grow with the session count and a burst of launches wants up to a core, so the old limits OOM-killed or throttled it well before that. The pod's QoS class becomes Burstable; on a large cluster raise the memory request to the limit. See "Sizing the agent stack" in docs/explanation/capacity.md.
- CRDs synced from the operator (workspace run modes): `Agent.spec.workspaceSecurity` (`rootMode` `userns`/`host`/`forbid`, `userNamespaces` `rootOnly`/`always`, `rootFeatures` `promote`/`downgrade`/`reject`, `profile` `baseline`/`restricted`, `sudo`, `supplementalGroups`, `fsGroupChangePolicy`) is how session containers run: uid 1000 by default, and host uid 0 for an image that needs root (`rootMode: host`, the default; `userns` for uid 0 in a pod user namespace). A CEL rule rejects `sudo` with `profile: restricted`. `KasmWorkspace.spec.hostUsers` (`false` puts the pod in its own user namespace). Schema only.
- CRDs synced from the operator (image puller: per-node DaemonSets with a storage budget): `KasmImagePuller` is reworked around a per-node holder pod plus one pull pod at a time within a disk budget. New `spec.storage` (`ImagePullerStorage`: `reservedBytes`/`reservedPercent`, `evictionPercent`, `unpackFactor`, `maxConcurrentPulls`), `PulledImage.priority` (pull order), and a much richer `status` (`holders`, per-node `nodes[]` with budget/staged/pulling/skipped, `pullFailures[]`, `summary.imagesSkipped` replacing `imagesPending`, `status.daemonSet` gone). `Agent.spec.imagePuller` gains the same `storage`, and `Agent.status` a new `ExtraImagesStaged` condition. Schema only. The puller now writes per-image pull-credential Secrets to read image sizes from the registry; the operator's Secret access stays namespaced (granted by the kasm-agent-instance chart, not this ClusterRole).
- CRDs synced from the operator: `Agent.spec.sessionProxy` gains `internalService` (a second Service in front of the same proxy pods — e.g. an internal `LoadBalancer` on a private subnet so a control plane on a peered network reaches this agent without a public path; same shape as `service`, pair it with split-horizon DNS) and `resolver` (the DNS server nginx uses to resolve a downstream agent's hostname for the `/desktop` relay, whose upstream is an nginx variable; unset uses the pod's cluster DNS). Schema only.
- RBAC synced from the operator: the API server's addresses for the session proxy's egress NetworkPolicy are now read from the `default/kubernetes` EndpointSlices instead of the deprecated Endpoints API, so the operator (`controller-manager`) ClusterRole reads `discovery.k8s.io/endpointslices` (`get`/`list`/`watch`) and no longer reads core `endpoints`. RBAC only; the policy it renders is unchanged.
- CRDs synced from the operator (a ServiceAccount of the sessions' own): `KasmWorkspace.spec.serviceAccountName` names the ServiceAccount the workspace pod runs under; the operator creates `<agent>-workspace` per Agent (no RBAC, token automount off) and the agent sets it on every session, so cluster policy such as an OpenShift SecurityContextConstraint can be granted to sessions without widening the namespace's `default` account. Empty keeps the namespace default. Schema only.
- CRDs synced from the operator (warm-pool controllers moved off the main line): the operator no longer owns the `pools.kasm.ai` WarmPool CRDs, so this chart drops both `warmpools` and `warmpoolinstances`, the `controller-manager` ClusterRole's `pools.kasm.ai` rules, and the WarmPool/WarmPoolInstance aggregate admin/editor/viewer roles — nine convenience roles remain, for the three `agent.kasm.com` kinds. Removal only; a WarmPool CRD already on a cluster is left in place (the `crds/` mechanism never deletes CRDs).
- CRDs synced from the operator: `KasmWorkspace`'s `healthCheck` (`WorkspaceHealthCheck`) description now spells out the default readiness — the operator marks a workspace Ready the moment VNC listens by execing bash to poll the port every 50 ms instead of waiting on the next whole-second TCP probe; an image without bash must set `readinessProbe` (e.g. a plain TCP probe). Description only.
- CRDs synced from the operator (bound where the session proxy connects): `Agent.spec.sessionProxy.networkPolicy` (`enabled`, `extraEgress`) is an opt-in egress NetworkPolicy the operator creates for the proxy pods, limiting their egress to their own and the control plane's namespaces, DNS and the API server plus `extraEgress`; ingress stays open. So it can resolve the session-proxy route table's targets, the operator (`controller-manager`) ClusterRole now also reads `endpoints` (`get`/`list`/`watch` in the core group). Schema and RBAC.
- CRDs synced from the operator (stop the image puller's disk-pressure eviction loop): `KasmImagePuller.status.nodeBackoffs[]` gains `diskEvictions`, `imageSetHash`, `recoveredAt` and `suspended`. The operator now pulls each staged image in its own init container (peak scratch is one image, not all at once), holds the newest Failed pod on a node until the template excludes it (so the DaemonSet keeps its own back-off), and treats disk-pressure evictions as slow to recover — a 15m re-check floor, a per-node eviction count that survives recovery, and suspension of a node after three evictions for the same image set (surfaced on the CR's `Degraded` condition). Status/behaviour only; the chart carries the schema.
- CRDs synced from the operator (a session proxy that scales and stays put): `Agent.spec.sessionProxy` can now be sized to load and placed deliberately, and `routing` defaults to `dynamic` — nginx resolves each session per request from a table the sidecar keeps current, with no reload (so churn no longer piles up nginx worker generations); the default `kasmweb/nginx` image carries the njs module it needs — rather than `static` (an nginx location per session, reloaded on every change). New fields: `resources`/`sidecarResources` (proxy requests so a node autoscaler counts the pod), `nodeSelector`, `tolerations`, `affinity`, `topologySpreadConstraints`, `podDisruptionBudget` (one of `minAvailable`/`maxUnavailable`), `drainTimeoutSeconds` (default 300 — how long a stopping pod keeps serving the streams it holds), `nginx` (`workerProcesses`/`workerConnections`), and two mutually exclusive ways to size the Deployment by live session count: `autoscaling` (`sessionsPerReplica`, `minReplicas`, `maxReplicas`, `scaleDownStabilizationSeconds`), which the operator drives, or `externallyScaled` for a KEDA/HPA. `Agent.status` gains `sessionProxy` (`replicas`, `desiredReplicas`, `scaleDownSince`). To manage the session proxy's `PodDisruptionBudget`, the operator (`controller-manager`) ClusterRole now also grants `policy/poddisruptionbudgets` (`get`/`list`/`watch`/`create`/`update`/`patch`/`delete`); without it the operator's cache cannot sync and it will not start. Schema, status and RBAC.
- CRDs synced from the operator (capacity that can grow): the `Agent` gains an opt-in `spec.workspacesAutoscaling` block with two independent halves. Its `enabled` (with `maxNodes`, `schedulingTimeoutSeconds`) tells the agent a node autoscaler can add nodes, so it counts addable nodes as capacity, stops withholding an image that would fit a new node, and (via a new agent-set `KasmWorkspace.spec.schedulingTimeoutSeconds`) keeps an unschedulable workspace `Pending`/`WaitingForCapacity` until a node arrives rather than failing it in seconds. Nested `spec.workspacesAutoscaling.standby` (`enabled`, `replicas`, `externallyScaled`, `image`, required `priorityClassName`, `resources`) keeps a Deployment of low-priority pause-container placeholders sized to the largest workspace in the catalog, so a session takes the room instantly and the evicted placeholder triggers the autoscaler. Each half works on its own — `enabled` is optional, so standby can run without it (standby covers normal load, waiting covers the bursts). `Agent.status.workspaces` gains `largestRequest` (what a placeholder must request) and `launchable`. Both default off; schema only, and the operator manages the placeholder Deployment with its existing RBAC (the `PriorityClass` is admin-provided), so no RBAC change.
- CRDs synced from the operator: `kubectl get agent` now answers whether the agent is working. `Agent.status` gains a `workspaces` object (`sessions`, `nodes`, `cores` — what the last heartbeat told the manager, `cores` being the reported capacity in image cores) and a `Registered` condition the agent writes about whether the manager is accepting its heartbeats. The default columns become `PHASE REGISTERED SESSIONS CORES WITHHELD MANAGER`, and `-o wide` adds `NODES`, `CPU%` (`workspaceCPURequestPercent`), the `DEGRADED` reason, `ZONE` and the workspaces node selector. Status and columns only — the agent writes `Registered` through the same `agents/status` access the `ImagesWithheld` condition already uses, so no new RBAC. A follow-up corrects the `serverID` field descriptions: when the spec pins no id the agent (not the operator) generates it, persists it in the `kasm-agent-state` ConfigMap and now reports it in `status.serverID`.
- CRDs synced from the operator: `Agent` gains `spec.workspaceCPURequestPercent` (1-100, default 100) — the share of a workspace image's `cores` a session reserves as its Kubernetes CPU request, so lowering it bin-packs more sessions per node without touching any CPU limit. `Agent.status` also documents the new `ImagesWithheld` condition the agent writes on its own `Agent` when it keeps an image out of what it reports to the manager because no node has room for it. To let the agent write that status, the `kasm-agent` ClusterRole now also grants `get` on `agents`, `get`/`update`/`patch` on `agents/status`, and `create`/`patch` on `events`; without them the agent only logs a warning and behaves as before.
- `Agent` gains `spec.seccomp` (`{backend, installer}`, backend `installer` or `spo`), which the operator reconciles into one of two seccomp backends. For `installer` the operator deploys a per-agent installer DaemonSet, and the chart ships a `kasm-seccomp-installer` ClusterRole (`configmaps` get/list/watch); for `spo` the operator instead binds the agent to a new `kasm-agent-seccomp-spo` ClusterRole (`seccompprofiles` get/list/watch/create/delete on `security-profiles-operator.x-k8s.io`) so the agent can create the cluster-scoped `SeccompProfile` resources the external Security Profiles Operator installs. `manager-role` grants the operator `bind` on both ClusterRoles (plus the existing two) and, for the spo finalizer/health probe, `seccompprofiles` list/delete. The chart carries the schema and all the RBAC; it does not install the Security Profiles Operator.
- CRDs synced from the operator (image-puller consolidation): `Agent` gains `spec.imagePuller` (`enabled`, `refreshIntervalSeconds`, `extraImages`, `resources`) and `KasmImagePuller` gains `spec.refreshIntervalSeconds`, so a single puller per agent — maintained from the manager's catalog plus any pre-seed extras, re-pulling mutable tags on the interval — replaces the separate manager-driven and chart-rendered pullers.
- CRDs synced from the operator (2026-09-15, image-puller rollout gating): `KasmImagePuller.status.summary` gains `imagesPending`, and the spec descriptions state the operator's new rollout rule. A change to the image set is a new DaemonSet pod template, and the kubelet finishes a replaced puller pod's remaining pulls before it honours the deletion, so every rollout that landed mid-pull stacked another pod per node pulling the same images. The operator now applies a template change only once no puller pod is still pulling; images added or removed in the meantime accumulate and go out together, the CR reports `Progressing=True` with reason `RolloutDeferred` while it waits, and a pull that has given up (`ImagePullBackOff`) does not hold it. The image list is staged sorted, so a reordered catalog is not a rollout, and the DaemonSet's `maxSurge` is `100%` so nodes roll in parallel instead of one at a time. The chart carries only the schema.
- CRDs synced from the operator (2026-09-15, image-puller back-off bookkeeping): `KasmImagePuller.status.nodeBackoffs[]` gains `lastEvictedPodUID`, and the descriptions no longer promise that the puller's back-off excludes nodes through its DaemonSet pod template. That exclusion is gone: every change to the back-off list rolled the DaemonSet and aborted the pulls in flight on all nodes. The kubelet's own admission and the DaemonSet controller's back-off cover a node under pressure; `status.nodeBackoffs` stays as bookkeeping.
- CRDs synced from the operator (2026-09-15, server labels and workspace tolerations): `Agent` gains `spec.labels` (server labels advertised in every heartbeat) and `spec.workspacesTolerations` (tolerations for every workspace pod, also scoping the agent's puller and capacity report); `KasmWorkspace.status` and `KasmImagePuller.status.nodeBackoffs[]` gain `lastOOMKilledAt`, the termination time of the last OOM kill already counted, so a container that restarts before the next reconcile is still counted once.
- `manager-role` grants `get`, `list` and `watch` on `nodes` instead of `get` alone. The operator reads a Node through controller-runtime's cached client when an eviction/OOM back-off window closes, and that client starts a Node informer on first use; with `get` only the informer's list was forbidden, the read never returned, and every workspace whose window had just closed stayed `Pending` with its replacement pod `Running` until the operator was restarted.
- The controller-manager pod template now carries the `kasm.com/security` and `kasm.com/healthcheck` annotations unconditionally. They are the markers this repository's Kyverno gates key off, and without them the operator Deployment was skipped by the workload-hardening and probe policies entirely — it was only ever checked for host namespaces. The pod and container securityContexts gain the fields those gates require and the Deployment did not state: `fsGroupChangePolicy: OnRootMismatch` on the pod (a no-op, since no `fsGroup` is set), and `runAsNonRoot: true` plus `seccompProfile.type: RuntimeDefault` restated at container scope, where the pod-level values already applied. No runtime behavior changes.
- `kasm-nginx-sidecar` ClusterRole now also grants `services` get/list/watch, mirroring the operator repo's regenerated `nginx_sidecar_clusterrole.yaml`: the sidecar watches a session's workspace Service directly instead of polling DNS, which raced the Service record's own propagation. Reads only; the role still grants no write verb on anything.
- `manager-role` no longer grants any access to Secrets. The operator only ever reads, creates and updates the per-workspace storage-mapping Secret by name, so that access is granted per namespace by the `kasm-agent-instance` chart (`operatorRBAC.*`) wherever an Agent is installed.
- `manager-role` ClusterRole narrowed to match the operator, which does not cache Secrets: `secrets` is get/create/update only (no list, watch, patch, delete), `persistentvolumes` and `clusterrolebindings` drop list/watch (and patch), `rolebindings` drops delete. Every other rule is unchanged.
- CRDs updated from the operator (2026-09-04): `Agent` gains `spec.sessionProxy.otel.endpoint` (session-proxy sidecar OTLP endpoint override; empty disables the exporter), and `KasmWorkspace.spec.fileMappings[]` gains `binaryData` (binary file content, mirrors a ConfigMap's `binaryData`) and `writable` (copy-on-start so the session user can edit the file).
- README lists all five CRDs it owns, adding `warmpools` and `warmpoolinstances` in `pools.kasm.ai`; the regeneration hint says `make readme-all`; the first section links the docs index. The HTML values-table template moved to the shared `_templates.gotmpl`.

- The default `image.repository` is `kasmweb/agent-operator` (was `kasmweb/kasm-agent-operator`); the monorepo apps dropped their `kasm-` prefix, and the image names follow the app names.
### Added

- `global.cattle.systemDefaultRegistry`: when set, it replaces the registry part of every image the chart renders and the per-image `registry` values are ignored, following Rancher's convention for the system default registry it injects on air-gapped clusters. Empty by default, so nothing changes outside Rancher.
- Initial release: installs the `agent.kasm.com` CustomResourceDefinitions, the static cluster RBAC the operator and the workloads it reconciles require, and the controller-manager Deployment.
