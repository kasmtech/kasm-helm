{{- if $externalAddress }}
The Kasm URL above is the address the cluster assigned to the {{ $proxyType }} Service, read back at
render time. It is reachable from wherever that address routes - on a local kind or k3d cluster
that is the container network, not your workstation.
{{- else if eq $proxyType "LoadBalancer" }}
The proxy is published by a LoadBalancer Service; browse to https://<address> once the cloud
provider (or MetalLB, or k3s ServiceLB) has assigned one:

kubectl get svc --namespace {{ .Release.Namespace }} {{ .Release.Name }}-proxy-ext-default -o jsonpath='{.status.loadBalancer.ingress[0].ip}{.status.loadBalancer.ingress[0].hostname}'; echo

Helm renders these notes before it creates anything, so the first install cannot show the
address. From the next `helm upgrade` on (same values) it is read back and printed above.
{{- else if eq $proxyType "NodePort" }}
The proxy is published on a NodePort; browse to https://<any node address>:<port>, where port is:

kubectl get svc --namespace {{ .Release.Namespace }} {{ .Release.Name }}-proxy-ext-default -o jsonpath='{.spec.ports[0].nodePort}'; echo

Pin the port with proxyService.nodePort and the URL is printed above from the first install.
{{- else }}
Nothing publishes the proxy outside the cluster{{ if $fronted }} by hostname{{ end }}. Reach it with a port-forward:

kubectl port-forward --namespace {{ .Release.Namespace }} svc/{{ $proxySvc }} 8443:8443    ->  https://localhost:8443
{{- end }}

Before anyone else uses it, set publicAddr to the DNS name users will type - it becomes the
certificate name, the Ingress/Route/Gateway host, and the address Kasm advertises to agents -
and helm upgrade.
{{- end }}
