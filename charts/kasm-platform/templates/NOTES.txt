================================================================================
BOTH HALVES ARE IN ONE RELEASE AND ONE NAMESPACE — four things to check
================================================================================

{{- if $authDomain }}
1. THE AUTH DOMAIN — seeded at database initialization. Nothing to do on a fresh install.
   `kasm-helm.kasmConfig.authDomain` is set to {{ $authDomain }}, so the Kasm Authorization Domain
   was written into the seed before the database came up. The session cookie is scoped to
   {{ $authDomain }} and reaches the agent's session proxy on
   {{ $publicHostname | default "sessions.example.com" }} as well as the control plane on
   {{ $publicAddr | default "kasm.example.com" }}.

   Confirm both hostnames really are under {{ $authDomain }} — a mismatch still 401s.

   This only applies to a database this release initialized. If you pointed the release at an
   EXISTING Kasm database, the seed never ran and the value is still whatever that database holds:
   change it in the admin UI under Settings -> Auth, or through the admin API:

     POST /api/authenticate            {"username":"admin@kasm.local","password":"..."}   -> token
     POST /api/admin/get_settings      {"username":"...","token":"..."}                   -> setting_id of kasm_auth_domain
     POST /api/admin/update_setting    {"username":"...","token":"...","setting_id":"...","value":"{{ $authDomain }}"}
{{- else }}
1. THE AUTH DOMAIN — MANUAL STEP REQUIRED after the first install.
   The Kasm Authorization Domain starts at its `$request_host$` default. That scopes the session
   cookie to the control plane's hostname, the browser never sends it to the agent's session
   proxy, and every session connection fails with a 401. Set it to a parent domain covering BOTH
   hostnames — for {{ $publicAddr | default "kasm.example.com" }} and
   {{ $publicHostname | default "sessions.example.com" }}, that is their shared parent.

   Do it in the admin UI under Settings, or through the admin API:

     POST /api/authenticate            {"username":"admin@kasm.local","password":"..."}   -> token
     POST /api/admin/get_settings      {"username":"...","token":"..."}                   -> setting_id of kasm_auth_domain
     POST /api/admin/update_setting    {"username":"...","token":"...","setting_id":"...","value":"<domain>"}

   On a FRESH install you can skip all of that: set `kasm-helm.kasmConfig.authDomain` to the shared
   parent domain and it is seeded at database initialization.
{{- end }}

2. THE ZONE MUST USE DIRECT CONNECTIONS.
   The seeded zone defaults route session traffic through the control-plane proxy, which 404s
   behind host-routing ingress. On a fresh install, preseed the zone instead:

     kasm-helm:
       kasmConfig:
         generatePreseed: true
       kasmZones:
         - name: default
           proxy_hostname: {{ $publicAddr | default "kasm.example.com" }}
           proxy_connections: false
           upstream_auth_address: {{ $publicAddr | default "kasm.example.com" }}

   On an existing control plane the preseed no longer runs — change Proxy Connections and Upstream
   Auth Address in the admin UI under Infrastructure -> Zones.

3. NAMESPACE LABELS (usually none needed).
   Sessions work without labels: the operator's per-workspace NetworkPolicy admits the session
   proxy by podSelector, and all traffic to workspaces flows through it. Label this namespace
   `kasm.com/role=manager` only if something here needs DIRECT ingress to workspace pods.

================================================================================
UNINSTALL IN TWO STEPS
================================================================================
`helm uninstall` deletes the Agent custom resources and the operator that clears their finalizers
at the same time. If the operator dies first, the deletions hang — and a later operator install
processes the stale deletion and tears things down. Always:

  kubectl delete kasmworkspaces.agent.kasm.com --all -n {{ .Release.Namespace }} --wait
  kubectl delete agents.agent.kasm.com --all -n {{ .Release.Namespace }} --wait
  helm uninstall {{ .Release.Name }} -n {{ .Release.Namespace }}
{{ else -}}
================================================================================
UNINSTALL
================================================================================
  helm uninstall {{ .Release.Name }} -n {{ .Release.Namespace }}

The control plane's PersistentVolumeClaims (the database, and any backup volume) survive an
uninstall. Delete them deliberately, once you are sure.
