# Changelog

All notable changes to the kasm-agent-instance chart are documented here.

## [Unreleased]

### Fixed

- `inClusterControlPlane` is nullable: unset (the new default, `null`) it follows the umbrella's `global.kasm.inClusterControlPlane`, and only without that is it off. Rancher's install form can submit an untouched toggle as `null`, which deletes an umbrella's per-subchart override and left a zero-config `kasm-platform` install failing on `agent.publicHostname is required`. An explicit `false` still wins.

### Changed

- `imagePuller.storage` sizes the per-node disk budget the puller pulls into (`reservedBytes`/`reservedPercent`, `evictionPercent`, `unpackFactor`, `maxConcurrentPulls`; empty leaves the operator's defaults), and `imagePuller.extraImages[].priority` (integer, default 0) orders the pull on each node — higher first, so a high-priority pre-seed pulls ahead of the catalog. Whether pre-seeded images staged is on the Agent's new `ExtraImagesStaged` condition. Because the operator now creates and patches per-image pull-credential Secrets, the namespaced operator `Role` this chart stamps gains `patch` on `secrets` (alongside get/create/update).
- `sessionProxy.internalService` provisions a second Service (same fields as `sessionProxy.service`) in front of the proxy pods — typically an internal `LoadBalancer` on a private subnet so a control plane on a peered network or in another region reaches this agent without a public path; pair it with split-horizon DNS that resolves `publicHostname` to it from the control plane's network and to the primary Service from browsers. `sessionProxy.resolver` sets the DNS server nginx uses for the `/desktop` relay's variable upstream (empty uses the pod's cluster DNS). Both off/empty by default.
- `sessionProxy.networkPolicy` (`enabled`, `extraEgress`) is an opt-in egress NetworkPolicy the operator creates for the proxy pods, limiting where they can connect — their own and the control plane's namespaces, DNS, the API server — so a rogue route cannot send a session's forwarded credential just anywhere; `extraEgress` adds rules in NetworkPolicy's own `egress:` terms (e.g. an `ipBlock` for a control plane outside the cluster). Needs a CNI that enforces NetworkPolicy. Off by default.
- `sessionProxy.routing` (`static` or `dynamic`) now defaults to `dynamic`, and the default `kasmweb/nginx` image carries the njs module it needs. `dynamic` resolves each session per request from a table the sidecar keeps current, with no reload, so heavy session churn no longer stacks up lingering nginx worker generations; `static` writes an nginx location per session and reloads on every change. Set `sessionProxy.routing: static` to keep the old behaviour.
- The session proxy can be sized to load and placed deliberately. `sessionProxy.autoscaling` (`enabled`, `sessionsPerReplica`, `minReplicas`, `maxReplicas`, `scaleDownStabilizationSeconds`) has the operator scale the proxy Deployment by how many sessions the agent runs — the load a websocket relay actually carries, which a CPU-based autoscaler would miss; `sessionProxy.externallyScaled` instead hands the replica count to a KEDA `ScaledObject` or HPA (as `workspacesAutoscaling.standby.externallyScaled` does), and the two are mutually exclusive. `sessionProxy.drainTimeoutSeconds` (default 300) is how long a stopping pod keeps serving the desktop streams it already holds before they are cut, so set it to how long a rollout or scale-in may take. `sessionProxy.nginx` (`workerProcesses`, `workerConnections`) sizes one pod's connection capacity. `sessionProxy.resources`/`sidecarResources` set the two containers' requests so the scheduler and a node autoscaler account for the proxy; `sessionProxy.nodeSelector`, `tolerations`, `affinity`, `topologySpreadConstraints` place the pods (keep them off a pool an autoscaler shrinks); `sessionProxy.podDisruptionBudget` (one of `minAvailable`/`maxUnavailable`) bounds voluntary disruption. Every block is omitted from the Agent while it holds only defaults, leaving the operator's own defaults in charge. See [Capacity](../../docs/explanation/capacity.md#scaling-the-session-proxy).
- Standby works out of the box: `workspacesAutoscaling.standby.enabled: true` is all it needs. The placeholder PriorityClass name defaults to a value derived from the agent (`<name>-standby`), and `workspacesAutoscaling.standby.priorityClass.create` (default `true`) has the chart create it with the negative `workspacesAutoscaling.standby.priorityClass.value`. Set `workspacesAutoscaling.standby.priorityClassName` to override the derived name, and `workspacesAutoscaling.standby.priorityClass.create: false` to reference a PriorityClass a cluster admin manages instead (a PriorityClass is cluster-scoped, so the derived per-agent name avoids clashes; give overrides distinct names). Rendering still fails if a created class's `value` is not negative. A created class sets `preemptionPolicy: Never`, so a placeholder never preempts other pods (only sessions preempt it). For demand-driven headroom, `workspacesAutoscaling.standby.externallyScaled` hands the placeholder Deployment's replica count to a KEDA `ScaledObject` or HPA you supply; see the capacity docs for a worked example.
- `workspacesAutoscaling` and `standby` surface the Agent's two opt-in capacity-growth features, which the operator now groups under one `spec.workspacesAutoscaling` block, and the chart values mirror that — `standby` nests under `workspacesAutoscaling` (both off by default). `workspacesAutoscaling` (`enabled`, `maxNodes`, `schedulingTimeoutSeconds`) lets a session wait for a cluster autoscaler to add a node instead of the launch failing when the pool is full — the agent counts addable nodes as capacity and holds the session `WaitingForCapacity` until a node joins or the timeout passes. `standby` (`enabled`, required `priorityClassName`, `replicas`, `externallyScaled`, `image`, `resources`) keeps a Deployment of low-priority placeholder pods that reserve room ahead of demand, so a session evicts one and starts at once while the evicted placeholder triggers the autoscaler to refill. The two work independently — enable `standby` alone for instant starts under normal load, add `workspacesAutoscaling.enabled` to also make bursts wait for a node rather than fail. Rendering fails if `workspacesAutoscaling.standby.enabled` is set without a `priorityClassName` (a negative-value `PriorityClass` the cluster admin creates). See [Capacity](../../docs/explanation/capacity.md#growing-capacity-autoscaling-and-standby).
- `workspaceCPURequestPercent` (1-100, default 100) sets the share of a workspace image's `cores` each session pod reserves as its Kubernetes CPU *request*. The manager's `cores` are a soft hint the Docker agent applied as a scheduling weight, but a Kubernetes request is a hard reservation, so at the default a mostly idle desktop fills a node's CPU long before it is busy. Lower it to bin-pack more sessions per node (`25` lets four 1-core sessions share a core's worth of requests); any CPU *limit* (on a *Quotas* image) is untouched, so sessions still burst to their full `cores`, and the agent scales the capacity it reports to the manager by the same factor so session accounting keeps matching what the scheduler can place. See [Capacity](../../docs/explanation/capacity.md#shrinking-the-cpu-request-without-changing-the-image).
- `publicPort` defaults to empty and is derived: 4444 while the hostname is derived in-cluster, the pinned `sessionProxy.service.httpsNodePort` when the proxy Service is a `NodePort`, 443 otherwise. An explicit value still wins. Rendering now fails for a `NodePort` proxy with neither a pinned node port nor a `publicPort`: the control plane dials `https://<publicHostname>:<publicPort>/` for its Hello before every launch, a random node port is never 443, and the only symptom was every session request answering "No Agent slots available" while the agent looked healthy. Set `publicPort: 443` explicitly if a load balancer or firewall in front forwards 443 to the node port.
- `workspacesTolerations` passes through to the `Agent`: the tolerations every launched workspace pod carries, which also scope the agent's own image puller and its capacity report to the nodes they tolerate.
- `agentLabels` and `workspaceLabels` are extra Kubernetes labels the operator stamps onto the workloads it creates from the `Agent`: `agentLabels` onto the agent Deployment, the session proxy and their Services and RBAC; `workspaceLabels` onto every session pod (a session's own labels layer on top). Both go into `metadata.labels`, never into the immutable pod selectors, so the agent's own workloads and its workspaces can be selected apart from each other and from the objects `commonLabels` already labels. See [Label the agent's workloads](../../docs/how-to/label-workloads.md).
- The image puller is consolidated into one puller per agent that the agent maintains from the manager's advertised catalog. `imagePuller.enabled` (now default `true`) is its master switch: set it `false`, together with `imageAvailabilityPolicy: all`, to run on demand instead of pre-pulling. `imagePuller.extraImages` pre-seeds images beyond the manager's catalog, and `imagePuller.refreshIntervalSeconds` re-pulls mutable tags on a cadence (0, the default, never re-pulls). The puller now follows `workspacesNodeSelector`/`workspacesTolerations`, so the removed `imagePuller.imagePullPolicy`, `imagePuller.images`, `imagePuller.nodeSelector`, `imagePuller.tolerations` and `imagePuller.affinity` are gone along with the standalone `KasmImagePuller` template; the puller is owner-referenced to the `Agent` and is removed when disabled or when the `Agent` is deleted.
- `seccomp` lets a workspace run under its image's inline seccomp profile (`security_opt: seccomp=<json>`) instead of `Unconfined`, since Kubernetes can only reference a profile already on the node. Off by default (`seccomp.enabled`), with a `seccomp.backend` of `installer` or `spo`. `installer` (default) deploys a per-agent DaemonSet that mirrors profiles onto the session nodes; it runs as root with a hostPath mount into the kubelet seccomp directory, so the agent namespace must admit the `privileged` Pod Security level and the nodes must allow hostPath (rules out e.g. GKE Autopilot), and `seccomp.installer.kubeletSeccompDir` overrides the kubelet seccomp root where a distro relocates it (k3s, microk8s). `spo` instead has the agent create cluster-scoped `SeccompProfile` resources for the external Security Profiles Operator (1.0+, which this chart does not install) — no hostPath or privileged namespace. Both follow `workspacesNodeSelector`/`workspacesTolerations`.
- `imageAvailabilityPolicy` is now honoured (it was previously injected but never read). It takes `pulled` or `all`; the default changed from `all` to `pulled`, which reports only images the puller has staged on a node, so the manager routes a workspace here only when it can start without a launch-time pull. `all` also reports catalog images not staged yet, for optimistic routing that pulls on demand.
- Removed `metricsIntervalSeconds` and `workspaceImagePullSecrets`: both reached the agent as env vars it never read. Metrics ride the heartbeat interval, and workspace image credentials come from the per-image registry settings in the manager (turned into a per-registry pull Secret on each session pod), or from `imagePuller.extraImages[].imagePullSecrets` for pre-seeded images.
- README lists the self-signed session-proxy Secret with its three render-time lookup cases (generate; reuse or regenerate when release-owned; leave untouched when created by anyone else), states that only one of the five exposure options renders and that `httpRoute`/`tlsRoute` need a non-empty `parentRefs`, cuts the LoadBalancer/NodePort, client-IP and older-operator material to the two value snippets and the 30000-32767 constraint (linking the how-to), and lists the required values with `inClusterControlPlane` in mind. The HTML values-table template moved to the shared `_templates.gotmpl`.

### Fixed

- `inClusterControlPlane` derived the manager hostname and session hostname but left the ports to the umbrella's values, and `kasm-platform` set `manager.port: 8080`, `manager.scheme: http` and `publicPort: 4444` unconditionally. Any install under `kasm-platform` that set `publicHostname` (every direct-connect, Ingress, HTTPRoute or passthrough example) therefore registered `<publicHostname>:4444`, the API's hello was refused, and every launch failed with "No resources are available". The chart now derives 8080/http and 4444 itself, and only while the matching hostname is derived; an explicit hostname takes the ordinary 443/https and `publicPort` (443).
- `httpRoute.parentRefs` and `tlsRoute.parentRefs` rendered only `name` and `namespace`, silently dropping `sectionName`, `port` and `kind`. They are passed through verbatim now, as the kasm-helm chart already did.
- `make images-agent` also missed every `KasmImagePuller.spec.images[].image` entry: its extractor did not match a key that opens a YAML list item (`- image: ...`), so the workspace images a release pre-pulls were absent from the airgap mirror list. Found by `make images-check`, which now extracts references with an independent structural yq walk instead of re-running the same awk (an earlier version could not fail).
- `sessionProxy.selfSigned` emitted its Secret even when one of that name already existed that the release did not own — the pre-created, bring-your-own case the value's own comment promised would work, and the exact flow `tests/values-agent/dev-parity.yaml` and `examples/kasm-agent/dev-cluster-values.yaml` document. Helm refuses to adopt a resource without its ownership metadata, so `helm install` failed with `exists and cannot be imported into the current release`. The template now reads the existing Secret's `meta.helm.sh/release-name`/`release-namespace` annotations: a Secret this release owns is reused (or regenerated when its `self-signed-for` marker no longer matches `publicHostname`), and a Secret anyone else created renders nothing at all, leaving the proxy to mount it by name.
- The five session-proxy exposure options (`ingress`, `httpRoute`, `route`, `tlsRoute`, `gatewayRoute`) could all be enabled at once, and `httpRoute`/`tlsRoute` rendered a route with no `parentRefs` — attached to no Gateway — without complaint. A new `templates/validation.yaml` (mirroring kasm-helm's) fails the render when more than one is enabled, or when either Gateway API route has empty `parentRefs`, naming the values involved.
- `make images-agent` omitted the session proxy's nginx sidecar. It matched only lines whose key was literally `image:`, and the sidecar is referenced at `Agent.spec.sessionProxy.sidecarImage` — so `docker.io/kasmweb/kasm-nginx-sidecar` never appeared in the generated list, and an airgap mirror built from it produced a session proxy that could not start (the proxy is a two-container pod). The extractor now matches any key ending in `image`, and a new `make images-check` target fails when the rendered manifests reference an image the list does not carry. Wired into the `docs-check` CI matrix.

### Added

- `openshift.scc.enabled` ships the SecurityContextConstraint the agent's sessions need on OpenShift and grants it to the `<name>-workspace` ServiceAccount the operator now runs every session under. OpenShift's default `restricted-v2` refuses what every workspace container does (start as root and `su` to `kasm-user`, add eight capabilities on top of `drop: ALL`, allow privilege escalation, pin `fsGroup: 1000`, reference a `Localhost` seccomp profile), and `anyuid` admits no capability adds. The SCC (`openshift.scc.workspace.name`, default `kasm-<namespace>-<name>-workspace`) admits exactly the operator's defaults; `openshift.scc.workspace.capabilities`, `allowPrivileged`, `allowHostPath` (device passthrough by path and Docker-style volume mappings render as hostPath), `volumes` (add `image` for Nix `imageMounts` on OpenShift 4.22+) and `seccompProfiles` widen it for what a catalog needs. With `seccomp.enabled` and the `installer` backend, the same switch grants the built-in `privileged` SCC to `<name>-seccomp-installer`, whose root hostPath DaemonSet sets the `spc_t` SELinux type. The agent Deployment, session proxy, image puller and standby placeholders set no UID and stay under `restricted-v2`. Off by default; the kinds are OpenShift-only.
- `global.cattle.systemDefaultRegistry`: when set, it replaces the registry part of every image on the `Agent` resource (agent, session proxy and sidecar, seccomp installer); `workspacesAutoscaling.standby.image` is a full reference and is passed through as written and the per-image `registry` values are ignored, following Rancher's convention for the system default registry it injects on air-gapped clusters. Empty by default, so nothing changes outside Rancher.
- Adds `inClusterControlPlane` (default `false`), which derives `manager.hostname`, the manager token Secret and `publicHostname` from a `kasm-helm` release installed under the same release name and namespace. Those three values otherwise have no default and fail the render, which is what made a Kubernetes agent impossible to install without a values file. Anything set explicitly still wins.
- Adds `sessionProxy.selfSigned.enabled` (default `true`), generating the Secret named by `sessionProxy.certSecretName` when cert-manager is not issuing one — the session proxy will not start without it. An existing Secret of that name is reused. On the default relayed topology this certificate is never shown to a browser; on direct-connect paths it must be replaced with a publicly trusted one.

- A namespaced `Role` + `RoleBinding` (`<fullname>-operator`), always rendered, granting the Kasm agent operator's ServiceAccount `secrets` get/create/update in this namespace: the operator's ClusterRole no longer carries any Secret access. `operatorRBAC.serviceAccount.name` names the ServiceAccount (default `controller-manager`) and `operatorRBAC.serviceAccount.namespace` where it runs (empty = this release's namespace; set it in the two-namespace layout).

### Fixed

- `tlsRoute` rendered `gateway.networking.k8s.io/v1alpha2`, which the Gateway API 1.5+ standard-channel CRDs no longer serve (`TLSRoute` graduated to `v1` in 1.5), so the chart-managed route was rejected by the API server on current clusters. The apiVersion is now chosen at render time: `v1` when the cluster serves it, `v1alpha2` when only the older experimental-channel CRD is served, `v1` when rendering offline, and the new `tlsRoute.apiVersion` value overrides all three.

### Added

- Initial release: creates the `Agent` custom resource (`agent.kasm.com/v1alpha1`) that the Kasm agent operator reconciles, plus its satellite objects — the manager token Secret, a cert-manager `Certificate`, and a `KasmImagePuller`.
- Adds five mutually-exclusive external-access options for the operator-created session-proxy Service (`httpRoute`, `ingress`, `route`, `tlsRoute`, `gatewayRoute`), session-proxy Service overrides with PROXY protocol support (`sessionProxy.proxyProtocol`), and a split-horizon `apiServerURL` override for manager ADMIN calls.
